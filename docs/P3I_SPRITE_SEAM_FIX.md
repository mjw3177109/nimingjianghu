# P3-I｜人物整身渲染修复与真正高清 Sprite 接入门禁

## 症状
1. 玩家在地图移动时，人物衣服/腰部出现明显水平断层，前一版各人物四方向SVG被当成正式动作Sprite；这些文件使用独立的`head`和`feet` clip path 后分段偏移，跨帧边缘断裂。
2. 原始完整PNG源图像素高约84～115，旧绘制固定42×58并在640×360视口显示；源图过度缩小，线条和衣料丢失。
3. 旧`?shenyan=16`候选只24×32/帧，同样不能用于高清游戏Sprite。

## 本阶段改动
- 浏览器/Windows只从`assets/sprites/*.png`显示**整张**原始人物PNG，在角色世界脚底位置锚定。
- 保持源图比例，网页目标显示高度80～100逻辑像素；人物渲染开启平滑取样，Tile仍以自己的32px拼接。
- 移动时整个人物最多位移1个像素，不得把头/衣/腿分层移动。
- 老`*_4dir.svg`和旧24×32候选依旧保留在艺术验收室用于对比，但不加载到可玩游戏。
- 新版批准的高清Sprite必须是PNG图集4×4且至少384×512。Pygame读取`sprite_manifest.json`，仅接受`direction_status=user_approved_independently_painted`且源图符合高分辨率合同的文件；网页读取同一正式资源注册表中的PNG。没有经过人工美术审批的候选不能通过正常运行路径调用。
- **首页和头像不动**；碰撞、任务、剧情、存档和互动对象不动。

## 视觉限制
旧源图最高115像素，无法通过设置网页像素缓冲区获得真正的高清角色动作帧。这一轮首先消除破裂、显著减少不必要的二次缩小。之后需要用Qwen生成独立的真实前后左右方向，每方向4帧，真实源图建议1024×1536+，打包成384×512高清游戏Sprite Sheet，并人工审核后接入。

## 测试
- `tests/p3i_sprite_integrity.cjs`：逐一检查原始PNG真实分辨率、完整人体显示、HDR源图大小门槛，确认代码不能再加载低清分段SVG和旧24×32预览。
- `tests/final_smoke.cjs`：保证青石镇→山贼→山洞秘籍→命痕→返回主城仍通关。
- Windows 4090 实机人工视觉验收仍需进行，自动测试不能证明“画面已经符合三张参考图”。

## 当正式高清母版准备好
先使用现有`tools/p3g_art_pipeline.py`生成384×512完整候选Sprite，再在美术验收室检查头身、服饰、步态。未经批准绝不自动覆盖游戏内资源。
