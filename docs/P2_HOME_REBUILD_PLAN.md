# 《逆命江湖》P2 首页重做可执行方案 V1.0
> 2026-10-19｜目标分支：`feat/playable-demo-v0.1`｜范围：P2 首页/启动流程；P3 图鉴仅预留入口，不越界重做玩法。

## 0. 不可改变的三张风格锚点
- 锚点 A《群侠绘卷》：六名精致国风 Q 版人物的五官、头身比、服装层级、水墨淡彩，作为人物画风唯一标准。
- 锚点 B《青石镇实机》：手绘立体场景、角色与环境比例、游戏 HUD、小地图、底部对白和功能栏，作为实际可玩界面唯一标准。
- 锚点 C《Demo 首页总览》：月夜武侠主视觉、左侧竖向导航、中间主角、右侧人物卡、下方三个玩法预览、最底部功能展示，作为首页布局唯一标准。
- 中文 AI 图片上出现的错字、错名**不能作为游戏设定**：以项目人物表里的`沈砚`、`廖`、`韩掌柜`、`顾青岚`、`苏晚晴`等正式 ID/名字为准。
- 禁止拿一张 AI 图片直接铺满整个网页来充当交互界面；背景、角色和装饰可以是分层图片，按钮、文案、交互、存档均由 HTML/CSS/JS 实现。
- 禁止把程序生成的扁平 SVG 占位当作正式美术；旧版资源可供降级预览，但最终正式发布门禁必须有审批后的生图资源。
- 本计划只规定“怎样做到”，不声明相关正式 PNG/UI 美术已经生成。

## 1. 本仓库实际情况（截至 P2 方案制定）
- `index.html` 直接呈现 `<canvas id="game" width="640" height="360">` 和侧边栏，没有单独主菜单。
- `game.js` 被 `index.html`直接引用后以 IIFE 自执行，初始化贴图并执行 `requestAnimationFrame(tick)`，首次进入约 500ms 后弹出开场对白。
- `game.js` 当前保存键是 `nimingjianghu_chibi_v02`，在 `updateUI()`写入本地存档；未经明确选择，打开网页也会触发初始化逻辑。
- `world-data.js` 统一配置三图玩法：`town`/ `road`/`cave`，已有 NPC、战斗、任务、秘籍与命痕触发点。
- `main.py` 是单独 Pygame 客户端，P2 仅改网页首页；同步 Windows 首页界面属于 P10，以免改动面失控。
- 当前 Q 版精灵是简化 SVG，不符合批准的三张高精度母图，不得简单放大充当 P2 最终角色立绘。

## 2. P2 成果目标
首次打开首页 `HomeScreen`，不开始任何地图逻辑。用户点击“开始游戏”才启动第一章，或点击“继续游戏”恢复经过校验的已有存档。
视觉上对齐锚点 C：左导航/中央主视觉/右四张卡/下方实机三宫格/底部五项介绍。
页面要在 1440×900 和 1920×1080 桌面显示器上保持主视觉完整，宽屏不拉伸；窄屏有层叠布局，主 CTA 可见。
所有可见文字由网页 DOM 绘制，不准从生图里复制乱码；图像须为单独可替换的 PNG/WebP。

## 3. 首页固定信息架构
### 3.1 左侧（桌面约21%）
- `逆命江湖` 项目 Logo：独立透明图层，旁边有红色小`DEMO`视觉标识。
- 主按钮 `开始游戏`：红色朱砂渐变，hover/focus/active/disabled 四态。
- 次按钮：`继续游戏`、`游戏设置`、`角色图鉴`、`剧情回顾`、`关于本作`。
- 禁止 6 个按钮仅是静态图；所有按钮必须绑定状态变化/交互。
- 没有存档时`继续游戏`禁用并显示“尚无存档”说明；有档才启用。

### 3.2 中间主视觉（约58%）
- 暖月轮廓、深蓝群山、灯火江湖城镇、樱花前景，画面层次为：远景→中景→主角→文字→局部粒子。
- 主角`沈砚`头身比例参照 A；应是主要视觉焦点，不得遮脸、改脸、改装。
- 标题文案固定：`逆天改命，再入江湖`；副标题：`这一次，你不再是旁观者。`
- 轻量鼠标视差：背景最多移动8px，人物最多移动4px；`prefers-reduced-motion` 禁用。
- 主角立绘透明背景；场景背景不预置按钮、不烘焙可读文字。
- 主视觉不能通过 CSS 任意裁切人物头部；使用明确安全区。

### 3.3 右侧角色卡（约21%）
`沈砚 / 苏晚晴 / 韩掌柜 / 廖`四张纵向卡片，各自拥有独立半身头像、姓名、短角色定位。
卡片 hover 高亮；点击至少可展开完整一句介绍（可复用侧栏），而非死控件。P3 角色图鉴实现后可改跳转；P2 不阻断展示。

### 3.4 下方三宫格
使用**从真实游戏中捕获**的青石镇、山路战斗、废弃山洞的预览截图：
- 标题：`青石镇·初入江湖`
- 标题：`山路·单人鏖战`
- 标题：`废弃山洞·命痕初现`
点击后显示玩法简介；若允许试玩进度定位，必须通过合法的状态迁移而不是跳过任务前置。
三张预览禁止使用尚未实现的“宣传画假截图”冒充可玩的正式实机。

### 3.5 最底部功能卖点
`多张地图 / 丰富剧情 / 角色养成 / 武侠战斗 / 精美 Q 版风格`，各项由 SVG/icon font 或正版图标独立实现。
卖点必须与本 Demo 已实现功能一致；正式未实现的功能标注“后续计划”，避免误导。

## 4. 精确布局技术基线
- 推荐桌面稿：1440×900 视口；`max-width:1600px` 居中；背景可铺满。
- 上半主舞台占首屏可见高度约 57～63%，下三宫格约 22～25%，页脚约 12%，具体以主视觉完整为第一优先级。
- 设计网格`grid-template-columns: minmax(245px, 21fr) minmax(520px, 58fr) minmax(230px, 21fr)`，gap 使用 clamp。
- `min-width: 1024px`使用横三列；小于 1024px 将右侧卡改为横向滑动卡行；小于 720px 仅展示简化主视觉和菜单，预览模块移到后续滚动区。
- 图文对比度 WCAG AA 为目标；首个可聚焦按钮必须是“开始游戏”。
- 图片: 背景优先 WebP（附 PNG fallback）；角色含透明 alpha 的 WebP 或 PNG；在构建或导出时控制首屏体积，避免 8 张全高清 PNG 并行阻塞。
- 不以`image-rendering:pixelated` 放大手绘稿。Canvas 场景与 UI 可以分别采用合适采样；保留 640×360 逻辑碰撞与 1280×720 游戏适配。

## 6. 状态机与保存协议
状态：
`HOME` → (`START_NEW` / `CONTINUE`) → `LOADING` → `PLAYING`；
`PLAYING` ↔ `PAUSED`；`HOME` ↔ `SETTINGS`/`CODEX`/`RECAP`/`ABOUT`。
- 初次进入：HOME，无脚本式开场弹窗，无 Canvas 运行事件。
- START_NEW：已有合法存档时弹二次确认，确认后才写新 GameState。
- CONTINUE：没有存档禁用；旧 `nimingjianghu_chibi_v02` 可迁移为版本化`nimingjianghu_save_v3`，迁移失败不能破坏旧存档。
- LOADING：异步预加载地图与核心精灵；完成后转 PLAYING，首次新游戏播放开场对白。
- RETURN_HOME：暂停游戏与 RAF（或严格阻止状态更新），保留内存 GameState，不会自动擦除存档。
- 游戏中的`restart`语义必须明确：`重新开始`与`返回首页`是不同操作，不能简单 reload 导致未知状态。
- `game.js`原先随`updateUI()`自动写入 localStorage；改为明确启动后`saveGame()`且仅保存白名单持久字段，不能在首页加载时写空白存档。
- 页面多个按钮连续点击必须幂等：同一帧连续触发`startNew()`只能启动一次 RAF。

## 7. 美术资产规格和拆图标准
详细见`docs/P2_HOME_ASSET_MANIFEST.json`。
- 背景应保留空旷城市/月亮安全区，适合承接中央主角透明立绘。
- 图片必须区分`concept_reference`（参考效果图）与`production_asset`（真实切图）。
- 禁止把“参考图 3 的整图”直接作为首页唯一静态背景。
- Hero人物后续固定从 A 标准母版派生，同一个沈砚，不重新绘制第二张不同脸。
- 右侧角色卡用官方头像，不要再生成似是而非的人物。
- 分开生成`menu_background`、`shenyan_hero`、角色半身像、预览图、边框装饰；可单独替换。

## 8. 推荐实施顺序（PR 内分阶段 commits）
1. `docs(p2): lock approved three-anchor homepage contract`：方案与资源 ID，锁角色和文案。
2. `refactor(web): defer game startup behind home state`：拆 GameApp 生命周期；新增启动/继续/返回和存档迁移，首先保证旧版剧情无回归。
3. `feat(home): implement interactive homepage layout`：HTML/CSS/JS 完整响应式交互，临时预览仅在 dev 下启用。
4. `feat(art): integrate approved painted assets`：替换正式分层图，优化首屏速度，出真实试玩截图。
5. `test(home): add homepage and progression smoke checks`：自动化测试+桌面/移动视口截图，检查浏览器控制台。
6. `docs(release): update screenshots and deployment`：README、提交验证、Vercel Preview READY。

## 9. 验收标准/阻断条件
### 视觉
- 首页左/中/右三大区域与参考图 C 的信息层级一致。
- 主角是一致的精致国风 Q 版，不能重新绘制异脸；无扁平 SVG 代替最终精美立绘。
- 不出现 AI 乱码、错名、错别字，所有游戏文本可选择且动态渲染。
- 四张角色卡外貌与图鉴官方母版同一人。
- 三张预览截图对应真实可玩的地图/战斗/山洞画面。
- 不出现游戏 HUD 覆盖首页、文字压住主角脸、滚动栏错位。

### 功能
- 首次访问只显示主页、不触发对白/战斗、不会生成默认存档。
- 新游戏点击进入青石镇，能完成旧版的 NPC对话→山路战斗→山洞获取秘籍→命痕结尾。
- 已有存档可继续；无档按钮禁用；返回首页后能恢复。
- 设置、角色卡、图鉴基础版、回顾、关于界面可操作；返回键/关闭键正常。
- 刷新首页不丢有效存档；切页不会重复注册 RAF / click 事件。
- 断网打开本地 index.html 时可运行静态菜单（不得使用 fetch 读取 file:// 不支持的数据）。

### 工程/发布
- `node --check game.js` 等 JS 静态语法检查通过。
- 自动浏览器冒烟测试至少覆盖：首页初始→新游戏→NPC对话→存档→返回首页→继续游戏。
- 对 1440×900、1920×1080、1024×768、390×844 至少四种视口取截图做人工确认。
- 构建结果与 GitHub commit SHA 匹配，Vercel 状态 READY，网页资源 HTTP 200 后才给用户最终试玩链接。
- P2 完成不等于完成 P3～P10；P2 视觉和首页交互必须单独验收。
